# Resale Hub

A mobile "selling hub" for resellers, by **Diddlerrr**:

1. **Find a deal (Search):** search once and see live eBay and Etsy results in one list, ranked by total price (item + shipping), with the best deal flagged. No account needed.
2. **Sell:** create a listing (title, description, price, condition, category, photos), pick a real eBay category, publish it to your own eBay seller account, then edit, republish or delete it from **My Listings**.

## What's real vs. what's not

| Marketplace | Search | Publish | Why |
|---|---|---|---|
| **eBay** | ✅ Browse API | ✅ Inventory API, per-user OAuth | Free developer program |
| **Etsy** | ✅ Open API v3 (images + US shipping) | ❌ | Etsy doesn't grant listing-creation scope to apps like this |
| Facebook Marketplace, Poshmark, Mercari, OfferUp, Depop | ❌ | ❌ | No public developer API |

Unsupported marketplaces are never faked; the Publish screen lists them as "Not available for publishing" and only lets you select ones that really publish.

## Architecture

Everything runs on free tiers: **Firebase Spark** (never Blaze) for Auth, Firestore and
Hosting; a **free serverless host** (Vercel recommended) for the API, because Spark can't run
Cloud Functions or make outbound calls; and **eBay Picture Services** for photos, because new
Firebase Storage buckets need Blaze.

- **Auth:** Firebase Authentication (email/password) via its REST API from the app; the API verifies Firebase ID tokens.
- **API:** one Express app (`backend/src`) deployed as a Vercel function at `https://<host>/api`. It holds the eBay secrets (host env vars only) and reaches Firestore with the Firebase Admin SDK over HTTPS.
- **Data:** Cloud Firestore (Spark). `users/{uid}` (profile + eBay settings), `users/{uid}/private/ebay` (OAuth tokens, server-only), `listings/{id}` (incl. a ~240 px preview). Clients can only read their own docs; all writes go through the API.
- **Photos:** shrunk on the phone, then sent through the API to eBay's Media API (`createImageFromFile`) with the seller's own token; the listing stores the returned `i.ebayimg.com` URL. Free, and nothing to clean up on our side.
- **eBay:** each user connects their own seller account (OAuth). After connecting, the API reads their business policies (Account API) and inventory locations and stores them per user; users can pick which to use or add a location by ZIP. Categories come from the Taxonomy API (`getCategorySuggestions`). eBay Marketplace Account Deletion notifications are handled.
- **Rate limiting:** per-user (per-IP when signed out) fixed-window limits: Firestore counters for upload/publish/search/sensitive routes, in-memory for cheap reads (saves Spark write quota).
- **Account deletion:** in-app (Account → Delete account) deletes listings and previews, eBay data, OAuth states, rate-limit counters and the auth record.

## Getting started

See **[docs/SETUP.md](docs/SETUP.md)**. Short version:

```bash
cp .firebaserc.example .firebaserc && firebase deploy --only firestore,hosting   # Spark-safe
cd backend && vercel link --project resale-hub-api && vercel env add …  && vercel deploy --prod
cd ../mobile && cp .env.example .env.local   # EXPO_PUBLIC_API_URL, EXPO_PUBLIC_FIREBASE_API_KEY
npx expo start
```

eBay OAuth callback (RuName accepted/declined URL): `https://resale-hub-api.vercel.app/api/ebay/oauth/callback`.
eBay account-deletion endpoint: `https://resale-hub-api.vercel.app/api/ebay/account-deletion`.

Tests: `cd backend && npm test` (Firebase Auth + Firestore emulators and a fake eBay server).

Brand assets are generated by `mobile/scripts/generate-brand-assets.py` (icon, adaptive icon, splash, favicon, Play feature graphic in `mobile/assets/store/`).
